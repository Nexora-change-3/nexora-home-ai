# NEXORA HOME AI — функциональная спецификация первой версии

Статус: рабочая спецификация, согласованные решения отделены от предложений.
Рабочая ветка: `feature/cloudflare-image-edit`.
Production `main` не изменять без отдельного решения.

## 1. Принципы первой версии

- Персональный инструмент для работы без обязательной регистрации.
- Сначала простое создание визуализации; проектные папки, размеры и планы не должны быть обязательными для старта.
- Интерфейс адаптируется под iPhone, планшет и компьютер.
- Реальные ограничения AI-провайдера сохраняются. В интерфейсе не вводить собственные искусственные лимиты/кредиты/тарифы для персонального режима.
- Не подключать платные сервисы и не включать платный тариф автоматически.
- Сначала тестировать в Cloudflare Pages Preview и отдельной feature-ветке. Не затрагивать GitHub Pages production.

## 2. Главный сценарий

1. Загрузить одно или несколько фото комнаты/ракурсов.
2. Выбрать один из 10 стилей или загрузить собственное фото-референс.
3. По желанию задать настройки отдельных элементов; пропускать настройки должно быть можно.
4. Нажать «Создать 3 варианта».
5. Просмотреть результаты, сравнить «До / После», выбрать лучший.
6. Редактировать интерьер нажатием на предмет.
7. Все версии автоматически сохраняются в локальной истории.

## 4. Экран результатов — утверждён вариант Б

- Один крупный результат на основном месте.
- Три миниатюры вариантов для переключения.
- Название варианта и стиль.
- Действия: «До / После», «Редактировать», «Сохранить», «Скачать».
- Возможность создать ещё три варианта.
- Открытие выбранного результата не должно скрывать доступ к другим двум.

## 5. Точечное редактирование

- Основной жест выбора — нажатие на предмет на изображении.
- AI определяет выбранный объект; при низкой уверенности просит подтвердить распознавание.
- Для замены предмета доступны оба способа: выбрать из каталога NEXORA или загрузить собственное фото.
- Утверждённые простые инструменты редактирования: «Изменить цвет» и изменение расположения предмета («Где?»).
- При замене одного предмета остальные элементы комнаты должны сохраняться максимально точно.
- Новая версия не перезаписывает исходную; нужна возможность вернуться к предыдущему результату.
- Не добавлять в первую версию дополнительные сложные режимы редактирования без нового согласования.

## 7. История и проекты

- История проектов и генераций.
- Хранить исходное фото, первоначальные три варианта, выбранный вариант, последующие редакции и изображения.
- Автоматически сохранять каждую генерацию и редакцию.
- Действия: открыть, продолжить редактирование, сравнить версии, восстановить предыдущую, скачать, удалить.
- Организация проектов по помещениям, типам объектов и статусам — необязательная, не должна мешать простому старту.
- «Мои референсы» отложены на последующий этап.

## 8. Экспорт и качество

- Максимальное качество и разрешение, которые реально поддерживает подключённая модель.
- Экспорт PNG и JPG; PNG — без дополнительного lossy-сжатия, JPG — компактная копия.
- Оригинальный результат хранить без повторного сжатия.
- Сохранять пропорции исходного помещения, когда это поддерживает модель.
- Не обещать математические 100% сохранения: целевой допуск пользователя — примерно ±10%, особенно для архитектуры и геометрии; это проверяется тестами.
- Максимально сохранять стены, планировку, окна, двери, проёмы, высоту потолка, перспективу и ракурс.
- Не менять предметы, которые пользователь не просил менять.

## 11. Текущая техническая база и известные ограничения

- Frontend сейчас: локальная PWA 0.4.4 на HTML/CSS/JS, IndexedDB; текущая модель данных — проекты, помещения, фото, планы, styleRefs, сметы.
- Текущий экран требует создания проекта и помещения вручную; это не соответствует утверждённому простому главному сценарию.
- Текущая генерация делает один запрос и сохраняет один результат в галерею фото, а не создаёт три отдельных варианта.
- Frontend уменьшает оба входных изображения до максимальной стороны 511 px и JPEG quality 0.86.
- Worker использует `@cf/black-forest-labs/flux-2-klein-4b`, принимает два изображения и запрашивает выход 1024×1024. Поэтому сейчас выход квадратный; максимальный выход и aspect ratio нужно перепроверить на поддерживаемых параметрах модели.
- Модель принимает до четырёх референсных изображений, входные изображения должны быть меньше 512×512. Это ограничение текущего провайдера/модели.
- Фактическое число генераций ограничено доступностью и квотой Cloudflare Workers AI, даже если внутри приложения не будет искусственного счётчика.
- Код Worker в GitHub и реально развёрнутый Worker расходятся по CORS allowlist: Preview origin присутствует в Cloudflare deployment, но отсутствует в файле репозитория. Перед следующим Wrangler deploy синхронизировать исходник и live-конфигурацию.
- Cloudflare API list secrets вернул пустой список, хотя пользователь ранее подтвердила наличие `NEXORA_ACCESS_KEY` в панели. Не просить заново вводить или пересоздавать секрет без проверки.
- Последний Preview deployment успешен: commit `453be39189d07047ca232437fa559069d5317cdd`. Production `main` не изменять.

## 12. План реализации и тестирования

1. Сверить текущие источники GitHub и live Cloudflare Worker, устранить дрейф конфигурации.
2. Подготовить новую простую главную страницу и модель данных генераций/версий, не ломая импорт старых локальных проектов.
3. Реализовать выбор стиля, фото комнаты/референса и создание трёх вариантов.
4. Реализовать экран результатов по варианту Б и сравнение «До / После».
5. Реализовать точечный выбор предмета, каталог/загрузку фото, изменение цвета и расположения.
6. Реализовать каталог, избранное, историю и автосохранение.
7. Реализовать экспорт PNG/JPG и адаптивность.
8. Проверить JavaScript, IndexedDB, импорт/экспорт, PWA cache и CORS.
9. Только после согласованного теста реальной генерации с фото пользователя проверить визуальное качество, квоту, три результата и сохранение архитектуры.
10. Все проверки — на feature branch и Pages Preview. Production оставить без изменений.
