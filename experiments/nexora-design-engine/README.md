# NEXORA DESIGN ENGINE — экспериментальный контур

Статус: архитектурная подготовка. Это не production-приложение и пока не содержит интеграции с генеративными моделями.

## Назначение

Создать собственную систему проектирования интерьеров, которая:
1. анализирует исходную фотографию и известные ограничения помещения;
2. формирует самостоятельную дизайнерскую концепцию до вызова графической модели;
3. переводит концепцию в структурированное задание;
4. передаёт задание независимому адаптеру графической модели;
5. оценивает результат по качеству дизайна, стилю, геометрии, функциональности и реализму;
6. сохраняет происхождение результата, параметры и оценки.

## Защитные правила проекта

- V1, V2, Production и существующие deployments не изменять.
- Эксперименты вести только в отдельной ветке.
- Не импортировать и не показывать старые неудачные генерации.
- Эталонный тест — только оригинальная фотография пользователя, когда она будет предоставлена.
- Не заменять её фотографиями из интернета или синтетическими изображениями.
- Исходник хранить отдельно от результатов; не перезаписывать.
- Не объявлять модель победителем по опубликованным benchmark-таблицам.
- Не подключать платные API, не создавать оплачиваемые ресурсы и не запускать крупные загрузки моделей без отдельной оценки стоимости и согласования.
- Любой критический дефект геометрии или функциональности блокирует выдачу, даже если изображение красиво.

## Папки

- `docs/ARCHITECTURE.md` — компоненты и потоки данных.
- `schemas/design-brief.schema.json` — машинно-проверяемый контракт задания.
- `evaluation/PROTOCOL.md` — одинаковые условия испытаний и критерии приёмки.
- `model-adapters/CONTRACT.md` — интерфейс подключаемой графической модели.

## Принцип разработки

Сначала система должна научиться проектировать, затем — управлять генерацией, затем — проверять результат. Генеративная модель является сменным рендер-движком, а не носителем всей логики NEXORA.
