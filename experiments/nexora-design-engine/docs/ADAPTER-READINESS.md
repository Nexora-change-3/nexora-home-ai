# Матрица готовности графических движков NEXORA

Статус: исследовательский документ. Это не подключённые адаптеры и не результаты инференса.

## Важное разграничение

В этом документе перечислены четыре **кандидатные графические модели** из исследования NEXORA. Они не подтверждают список четырёх сторонних приложений, о котором отдельно говорилось в прежнем плане интеграций. Эти две задачи нельзя смешивать.

Ни одна из моделей ниже пока не подключена к Render Orchestrator и не испытана на исходной фотографии пользователя. Ни одна не выбрана победителем.

## Кандидаты

| Модель | Лицензия по опубликованному репозиторию/карточке | Сильная сторона для проверки | Ограничение до интеграции |
|---|---|---|---|
| FireRed-Image-Edit | Apache 2.0 | Инструкционное редактирование, согласованность многоэлементных изменений; есть training/LoRA и ComfyUI-материалы | Оптимизированная конфигурация заявляет около 30 GB VRAM; это заявление проекта, не гарантия производительности NEXORA |
| Qwen-Image-Edit-2511 | Apache 2.0 | Image-to-image редактирование, заявленный акцент на консистентности и геометрическом/индустриальном дизайне | Модель 20B; проверить доступную аппаратную конфигурацию, память, скорость и качество именно интерьерных изменений |
| LongCat-Image-Edit | Apache 2.0 | Глобальное и локальное редактирование, работа с reference guidance и сохранением неизменяемых областей | Репозиторий модели около 29 GB; реальная память, скорость и режим локального редактирования требуют отдельной проверки |
| HiDream-O1-Image | MIT | Унифицированная генерация и редактирование; заявлен Prompt Agent и разрешение до 2048×2048 | Для полноценного редактирования авторы рекомендуют full model; CUDA GPU и совместимость окружения должны быть проверены |

Лицензии и технические сведения нужно повторно сверить с конкретной версией весов и условиями распространения непосредственно перед использованием. Лицензия репозитория сама по себе не подтверждает условия коммерческого API или всех сторонних компонентов.

## Принцип выбора

Не выбирать модель по общим benchmark-таблицам. Для NEXORA решающими являются:

1. Способность выполнить значимый редизайн, а не косметическую смену цвета.
2. Сохранение перспективы, проёмов и подтверждённых неподвижных элементов.
3. Правдоподобная мебель, материалы, освещение и масштаб.
4. Возможность управлять локальными изменениями и масками.
5. Различие трёх концепций по композиции и дизайнерской идее.
6. Повторяемость, время обработки, стоимость одного принятого результата.
7. Условия приватности, хранения и удаления пользовательских изображений.

## Последовательность интеграции

### Этап 0 — до подключения
- Проверить актуальные лицензии, model cards, зависимости и ограничения аппаратуры.
- Для каждого кандидата определить: локальный запуск или hosted endpoint, минимальную конфигурацию, цену, хранение изображений и регион обработки.
- Не создавать платные ресурсы и не отправлять пользовательские фотографии провайдерам без отдельного согласования.

### Этап 1 — технический прототип
- Реализовать отдельный адаптер на общий контракт из файла model-adapters/CONTRACT.md.
- Проверить валидацию входов/выходов, тайм-ауты, отмену, ошибки и фиксацию параметров на синтетических технических fixtures.
- Не считать mock-тест реальным вызовом модели.

### Этап 2 — сравнительное испытание
- Использовать один и тот же оригинал пользователя, один Design Brief и одинаковые ограничения для всех моделей.
- Сравнить каждый результат по единой матрице оценки и показать пользователю.
- Не заменять исходную фотографию и не импортировать старые неудачные результаты V1.

### Этап 3 — решение
- Выбрать одну модель или связку только после оценки реальных результатов, стоимости и приватности.
- Остальные адаптеры оставить сменными; не переносить эксперимент в V1/V2/Production автоматически.

## Предварительный порядок технической проверки

1. FireRed-Image-Edit — первым проверить доступность и соответствие задачам редактирования интерьера.
2. Qwen-Image-Edit-2511 — второй независимый кандидат для сопоставления.
3. LongCat-Image-Edit — отдельно проверить локальное редактирование и сохранение областей.
4. HiDream-O1-Image — проверить требования к полноценному режиму редактирования и стоимость аппаратуры.

Этот порядок — план проверки, а не рейтинг качества.
